# MicroTech LVGL Host Simulator (sim)

This directory is a standalone CMake project that is not wired into the root
ESP-IDF build; it renders the real UI code under `layers/` for development
debugging, agent driving, and CI regression. This README is the simulator's
single usage and contract document.

## Prerequisites (WSL2 / Debian / Ubuntu)

```sh
sudo apt install build-essential cmake ninja-build python3 python3-pip \
    libsdl2-dev libcurl4-openssl-dev
# Do not apt install libfreetype-dev to link sim: the distro 2.13.x does not
# match the device's 2.14.3.
# FreeType 2.14.3 uses the in-tree
# managed_components/espressif__freetype/freetype sources.
# sim's CMake needs $ENV{IDF_PATH} (tinycrypt sources/headers), so export the
# IDF environment first; resource and review dependencies
# (Pillow/PyMuPDF/pypng/lz4) are best installed into the IDF virtualenv (the
# system python3 may lack pip and these packages):
source ~/esp/esp-idf/export.sh
python -m pip install -r requirements-weather-assets.txt
```

`managed_components/lvgl__lvgl`, `espressif__cjson`, `espressif__freetype`, and
`espressif__libpng` must already exist, and `build/config/sdkconfig.h` must have
been generated by a previous `idf.py build` (sim's CONFIG mirror source). When
they are missing, CMake raises `FATAL_ERROR` and does not fall back to
FetchContent.

## Build

```sh
cmake -S sim -B build/sim -G Ninja -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
cmake --build build/sim
```

The LVGL options (DEMOS/EXAMPLES/THORVG=OFF, `LV_BUILD_CONF_PATH`) are already
fixed inside `sim/CMakeLists.txt`, so the command line does not need to repeat
them.

## Daily Development (Recommended Entry)

```sh
python3 sim/dev.py
```

The numeric menu keeps only the few things a human does daily: start the window
(optionally jumping straight to a page; online/offline, offline by default),
capture a page screenshot, reset device state, rebuild (incremental; while a
session is running it prompts that a restart is needed to take effect). Exit
(0 or Ctrl+C) always stops the simulator session first. All paths are injected
automatically (`build/sim/dev_nvs`, `build/sim/shots`, port 5002), zero
arguments; when there is no graphical display environment, starting
automatically falls back to headless residency. For headless driving, the
control tree, CI regression and golden samples, use `sim/tools/simctl.py` and
`sh sim/ci/run_ci.sh [--update]` directly. The dev entry validates the session
PID and the agent responses, and refuses to start when port 5002 is occupied by
another agent. A networked session uses the host's real HTTP/HTTPS; an offline
headless session uses the CI clock and issues no weather requests.

The dev entry also records the `DISPLAY`, `WAYLAND_DISPLAY`, `XDG_RUNTIME_DIR`,
and `SDL_VIDEODRIVER` values of the session at start. When you start it again
after reconnecting a remote desktop or switching graphical sessions, if the old
PID is confirmed to belong to this project and the display environment has
changed, it stops the old session automatically and restarts it in the current
environment; when the old process environment cannot be read it only warns and
never kills other processes by mistake. You can explicitly choose the SDL
backend when needed: `SDL_VIDEODRIVER=wayland python3 sim/dev.py` or
`SDL_VIDEODRIVER=x11 python3 sim/dev.py`. What the agent screenshot verifies is
the LVGL framebuffer, which is not the same as the desktop window having
rendered correctly; when the SDL window, renderer, or present step fails, see
`build/sim/dev_session.log`.

After the window starts it uses a fixed panel size and does not respond to edge
dragging; to change the display scale, start the simulator with
`--window-scale N`.

## Run

```sh
# Headless (the default path for WSL / agents / CI; falls back to dummy when
# DISPLAY is empty)
SDL_VIDEODRIVER=dummy ./build/sim/microtech_sim --headless --ci \
    --res-dir build/sim/sim_res_fs --agent-port 5002

# Window preview (needs WSLg or an X server)
./build/sim/microtech_sim --res-dir build/sim/sim_res_fs --agent-port 5002

# Smoke: run N simulator loop iterations, navigate to the given app via the
# mailbox, then exit
./build/sim/microtech_sim --headless --res-dir build/sim/sim_res_fs \
    --nvs-dir build/sim/sim_nvs --frames 60 --navigate weather \
    --out-dir build/sim/shots
```

CLI: `--headless`, `--ci`, `--res-dir <staged resource directory>`,
`--nvs-dir <NVS directory>`, `--agent-port N`, `--window-scale N`,
`--out-dir <screenshot directory>`, `--frames N`, `--navigate <app_id>`,
`--screenshot NAME`, `--brightness N`, `--key boot|power`,
`--swipe x1,y1,x2,y2[,steps]`, `--ci-step N`. In CI, `--frames N` advances
33 ms per iteration; outside CI each iteration pumps events and presents; `0`
means residency. A screenshot is only produced when `--screenshot` is given
explicitly; without `--out-dir` it goes to the current directory, otherwise
into that directory. The agent protocol (TCP JSON-RPC, default
`127.0.0.1:5002`, avoiding the on-device baseline port 5001) is documented in
`sim/tools/simctl.py`.

## Weather Integration (Live Network Data)

The HTTP data plane of a `--ci` session belongs exclusively to the script
(unregistered URLs count as offline), so weather can only be fed from
`sim/ci/fixtures/*.json` via `sim.set_weather` for deterministic regression and
**never goes online**. To see **live weather** in the simulator, use a
non-`--ci` mode (the networked session of `python3 sim/dev.py`, or a bare
`--headless` residency), and note:

- Run `sim.set_wifi {connected}` (`simctl set-wifi connected`) first so
  connectivity is ready;
- **Wait for the weather service to finish fetching**: data starts appearing at
  roughly 20 s, and location→current/alerts/hourly/daily all being fetched and
  stable as "… update" usually takes **1–2 minutes**; before that, a brief
  `缓存实况` ("cached live") / `服务降级` ("service degraded") display is a
  fetch transition state, **not a defect** — do not draw conclusions from it;
- **Direct connection by default, no proxy**: a proxy changes the egress IP and
  shifts the geolocation (for example landing on an overseas city), making the
  result inconsistent with hardware or a direct connection; enable a proxy
  temporarily only when the direct connection genuinely fails;
- When there is no data for a long time, check `sim.ping`'s `network_ready`, the
  weather state, and `build/sim/dev_session.log` in that order.

Weather freshness uses the host's real clock
(`weather_service_port_now_seconds` → `time(NULL)`), while `sim.set_time` only
affects the app clock: therefore the fixed fixture timestamps in CI are judged
expired, and the weather golden under `sim/ci/golden/ui/` only guarantees layout
regression and does not represent the live state; hardware syncs time via SNTP
and has no such difference.

## Real Sources Compiled into sim

- app_manager: all app_core runtime `.c` files + app_theme
  (`app_manager_persistence.c` is not compiled, so factory reset does not clear
  persisted keys); `HOST_TEST` is not defined, and the mailbox drains on the
  LVGL worker's `lv_timer` (as on hardware).
- apps: the built-in Apps and shared UI sources (the manifest is
  `layers/apps/app_sources.cmake`, shared by sim and the cross-layer suite
  rather than copied) are all compiled as executable sources, together with
  `sim/cmake/app_builtin_apps.ld` (`-Wl,-T`) to preserve the
  `.app_manager_apps` link section (the registry discovers all built-in Apps;
  `apps_persistence.c` is used only by `main/app_runtime.c` and is not compiled
  by sim).
- middleware: mt_log, event_bus, nv_storage (file backend `sim_nvs`),
  timer_service, power/imu/weather/time/chore/onboarding/factory_reset/
  connectivity/wifi/recorder, `sd_storage_service`, and the `file_service`
  business real sources. audio, the SD board-level adapter, and device_link keep
  `ports/fakes/`; SD files really live in a host directory, a normal unmount
  neither moves nor deletes the directory, and the capacity comes from
  `statvfs` (CI can pin it). Recording commands are executed asynchronously by a
  real host worker, list queries only read the cache; the shared SD revision
  drives the rescan without restarting the recording service.
- Not compiled: `system_pm`, `ble_runtime`, `wifi_service_idf_port.c`,
  `time_service_port.c`, `connectivity_manager_digest.c` (sim uses a real
  tinycrypt SHA-256 instead), the real bsp sources (sim_bsp provides the three
  `bsp_hal.h` contracts and the DISPLAY|TOUCH|INPUT capability surface). From
  `main/` only `app_product_config.c` is compiled, and at runtime
  `sim/runtime/sim_runtime.c` stands in for `main/app_runtime.c`.

**Boundaries sim does not cover** (verify on hardware; host tests are no
substitute): BLE radio/pairing/GATT, Wi-Fi scan and association/RSSI, the real
audio I2S path, `system_pm` standby/deep sleep, SD FAT formatting and
mount-failure semantics, the RTC alarm, DMA/QSPI timing, the actual reboot of a
factory reset. CI's SD capacity is a fixed value (see below) and does not
represent hardware `statvfs`.

## Known Device-Semantics Pitfalls

- The desktop LVGL build defines `LV_KCONFIG_IGNORE`, so the
  `CONFIG_LV_USE_CLIB_* → LV_USE_STDLIB_*` mapping in `lv_conf_kconfig.h` is
  compiled out: `lv_conf.h` must directly set
  `LV_USE_STDLIB_MALLOC/STRING/SPRINTF = LV_STDLIB_CLIB`, otherwise large
  FreeType allocations land on the 35 KB TLSF pool and fail (manifesting as
  `FT_New_Face error(0x40)`).
- With `LV_FREETYPE_USE_LVGL_PORT=1`, `ftsystem.c` must be removed from the
  freetype library and LVGL's `lv_ftsystem.c` compiled in, exactly as
  `espressif__esp_lvgl_adapter` does (CMakeLists:363-386); otherwise
  `FT_New_Face` goes through the host `fopen("F:font.ttf")` and fails.
- `lv_init()` (9.5) already calls `lv_freetype_init` internally; the shim must
  not init it again.
- The LVGL worker must be created through sim's
  `xTaskCreatePinnedToCore("lvgl", ...)`: the mailbox captures the worker
  identity with `xTaskGetCurrentTaskHandle()`.

## Resource Pipeline

`sim/cmake/resources.cmake` includes the shared
`cmake/mt_app_resources.cmake` (the same rule the firmware uses) and the two
manifest files `layers/apps/resource_manifest.cmake` and
`app_theme/resource_manifest.cmake`, converts PNGs with the in-repo
`managed_components/lvgl__lvgl/scripts/LVGLImage.py` to
`RGB565A8 --ofmt BIN --compress NONE`, stages them into `build/sim/sim_res_fs/`,
and generates `sim_res_meta.h` with `gen_res_meta.py` (file count + an mmap
checksum using the same algorithm as `spiffs_assets_gen.py`). Cross-check
consistency with the device:

```sh
diff -rq build/sim/sim_res_fs build/esp-idf/main/app_res_fs   # byte-identical
python3 sim/cmake/gen_res_meta.py \
    --assets-dir build/sim/sim_res_fs --output /tmp/meta.h \
    --check-res-bin build/mmap_build/app_res_fs/res/res.bin   # checksum parity
```

## Kconfig Auto-Sync and Configuration Drift Prevention

**sim's `sdkconfig.h` is neither committed nor maintained by hand**:
`sim/cmake/gen_sdkconfig.py` generates `build/sim/gen_inc/sdkconfig.h` verbatim
from `build/config/sdkconfig.h` (the authoritative expansion of the most recent
`idf.py build`, including the local private weather domain/token) on every CMake
configure and injects it with `-include`, matching the firmware macro for macro;
`CMAKE_CONFIGURE_DEPENDS` lists `sdkconfig.h/.defaults/build autoconf`, so a
change on either side regenerates it automatically on the next
`dev.py`/`cmake --build`.

Freshness gate: the CONFIG_ symbols actually referenced by the sources are
compared by value between `sdkconfig` and the expansion (historical leftovers in
`sdkconfig` do not participate, avoiding mtime/full-set comparison false
positives); on a mismatch the configure fails outright and points to
`idf.py build`.

```sh
python3 sim/ci/check_lv_conf.py   # lv_conf.h ↔ generated mirror ↔ defaults ↔ device autoconf
```

On the LVGL side a four-way check is still enforced, and the
CANVAS/SNAPSHOT/IMAGE/FREETYPE PORT/FS_POSIX=0 gates are mandatory (`lv_conf.h`
is a hand-written file for the desktop build, the Kconfig mapping is compiled
out by LV_KCONFIG_IGNORE, and it has to be kept consistent with the real
configuration manually, with the gate as the backstop).

## Agent Bridge

Without `--sd-dir`, every start creates a private `/tmp/mt-sd-XXXXXX` sandbox,
and only sandboxes owned by that instance may be simulated-formatted. An
explicit `--sd-dir DIR` can still be browsed, recorded to, and deleted from, but
format
returns unsupported; ordinary working directories are never formatted. The
recording full-path budget is 192 bytes (including NUL), and the file manager
full backend-path budget is 1024 bytes.

`sim.sd`'s mount/umount/format go through the real file worker and maintain the
generation bound at request submission. fail_mount/fail_format/fail_space inject
failures; fault reports a medium failure for recovery verification. The fixture
creates bounded Chinese directories and multi-page long-name files inside the
volume for UI review; write/clear hold MAINTENANCE when modifying the recording
directory and publish an SD revision, and are refused while a recording is in
progress.

`--agent-port N` (default 5002, bound to 127.0.0.1 only; 5001 is left for the
on-device baseline). The protocol is line-delimited JSON-RPC:
`{"id":1,"method":"sim.ping","params":{...}}` →
`{"id":1,"ok":true,"result":{...}}`.

Methods: `sim.ping`, `sim.step {ms}` (multiples of 33, CI only), `sim.wait_idle
{timeout_ms}` (frame hash unchanged for 2 consecutive steps +
`lv_anim_count_running()==0`; returns a top-level `error` while paused),
`sim.screenshot {name,wait_idle}`, `sim.tree {include_layers?}` (absolute
coordinates + computed `LV_PART_MAIN` style + type value + image semantic ID;
with `include_layers:true` the top/sys layers are appended in an `overlays`
array, and the task switcher lives on the sys layer), `sim.touch {action,x,y}`,
`sim.key {button,action}` (press/release/click), `sim.navigate {app}` (posts to
the mailbox, does not block), `sim.apps`, `sim.set_time {epoch}`,
`sim.set_power {voltage?,pct?,charging,vbus}` (voltage/pct may each be omitted;
a missing pct falls back to the voltage-derived display),
`sim.set_wifi {state}` (connected/disconnected), `sim.set_imu {pitch,roll}`
(degrees), `sim.set_weather {endpoint,status,body}` (loads the sim_http script
table then `request_refresh`, real parse chain), `sim.pause {enabled}`,
`sim.set_wifi_scan {records, request?, trigger?, wait_scan?, status?}` (loads
port scan records; `trigger` injects a real SCAN_DONE, `wait_scan` polls the
port scan window to ensure the event lands mid-scan, `request` first issues one
scan through connectivity_manager), `sim.sd {action:
mount|umount|write|clear|list|svc, name?, seconds?}` (mount/unmount a host
directory volume, synthesize a silent WAV, clear, list the
directory, read the recorder service cache index and generation; `svc` also
returns the target path list, operation_id/pending/last_error, the current
storage, and the generation/revision of the published index, for checking
asynchronous final states and same-path replacement protection),
`sim.nvs {action: get|set|erase, key, value?}` (real nv_storage string keys),
`sim.connectivity` (connectivity_manager and wifi_service state, scan cache
snapshot), `sim.switcher {get?|action?}` (task switcher
visibility/display/clear), `sim.control_center {get?|action: show|hide}`
(control center visibility/open/close; the top pull-down gesture can also be
reproduced with `touch`/`drag`), `sim.set_bluetooth
{enabled?,bound?,active?,client_connected?,window_remaining_ms?}`,
`sim.offer_pairing {token?,passkey?}`, `sim.exit`. Client:
`python3 sim/tools/simctl.py <command>`.

`sim.ping` returns `network_ready`, `weather_state`, `weather_failure`,
`active_app`, `ci`, `frames`, and `paused`. In CI sessions and while paused,
`active_app` is always `null` (a lifecycle query blocks through the mailbox);
use `sim.tree`/`sim.switcher` to determine the current page instead. `simctl`
fails fast when it cannot connect and suggests starting `python3 sim/dev.py`; on
a port conflict, stop the development session before running CI. When a real
networked request fails, check `network_ready`, the weather state, and
`build/sim/dev_session.log` first.

Failure responses use a top-level `error` and carry no `result`; success
responses use `result`. `sim.wait_idle` returns `error: "adapter paused"` while
paused; `sim.screenshot` waits for stability by default first, and a paused
frame requires an explicit `wait_idle:false`.

## Control Tree

`sim_agent_tree.c` walks `lv_screen_active()` while holding the lock. Node
fields:

| Field | Content |
| --- | --- |
| `type` | the name of the `lv_obj_class` (e.g. `lv_label`) |
| `coords` | absolute screen coordinates `x,y,w,h` |
| `flags` | `visible` / `clickable` / `scrollable` |
| `state` | `pressed` / `checked` / `focused` / `disabled` |
| `styles` | `LV_PART_MAIN` color, opacity, radius, padding, line height |
| `children` | child node array |

Labels additionally provide `long_mode` (`0 WRAP / 1 DOTS / 2 SCROLL / 3
SCROLL_CIRCULAR / 4 CLIP`), `max_lines`, `line_space`, `content_h`,
`lines_complete`, and `lines`. `content_h` is the text-available height after
subtracting LVGL style spacing. `lines` is split by rendering result, with
elements of `{"text", "w"}`: `text` is that line's source text and `w` is that
line's pixel width. `lines_complete` being `false` means the rendered-line
evidence is incomplete (for example exceeding the export limit or an allocation
failure); it does not mean the source text was truncated. `lines_complete: true`
means the line array is complete; an empty label corresponds to `lines: []` and
`true`. `text` is still the original non-auto-wrapped text; under DOTS mode the
trailing `...` that LVGL already replaced in place appears in both `text` and
`lines` (this is the basis for detecting truncation). Images provide
`image_semantic_id`; slider/bar/arc provide `value`/`min`/`max`; switch/checkbox
provide `checked`; dropdown/roller provide `selected`. A scenario's
`tree_assert.contains` does superset matching against node fields.

Lock discipline: tree/screenshot/hash hold `esp_lv_adapter_lock` read-only/copy;
step/navigate take no lock; touch/key only write atomic state. `pause` completes
the worker/flush fence before returning; `wait_idle` does not advance the tick
while paused. A CI session stays resident until `sim.exit` or a signal.

## Regression (sim/ci/run_ci.sh)

```sh
sim/ci/run_ci.sh                    # port preflight + check_lv_conf + build + staged parity + all scenarios
sim/ci/run_ci.sh build/sim --update # regenerate PNG goldens (commit after manual review)
```

**The scenario PNG auxiliary gate is currently suspended**: the firmware GUI is
still being adjusted, and the scenario baseline directory
`sim/ci/golden/scenarios/` is not yet committed; page review baselines use
`sim/ci/golden/ui/`. By default only tree assertions run; with an explicit
`SIM_PNG_GOLDEN=1` the comparison really happens, and **a missing baseline is a
FAIL** (generate with `run_ci.sh --update`, then commit after manual review).
`review_pages.py --check` independently owns the page state matrix, geometry
lint, and UI baseline comparison. A state can use `expect_absent` to assert that
an erroneous success prompt or a stale directory row is absent; recording states
combine the final state and target path list of `sim.sd svc` to validate that a
same-path replaced file is still in the index.

**tree_assert baseline convention**: the scenario text assertions represent the
current firmware UI snapshot. During GUI adjustment a `run_ci.sh` FAIL is a
regression signal — update the scenario assertions in the same commit for
intentional changes; an unexpected change means the gate is working.

**Full-page baseline (`review_pages.py`)**: when a page's scroll container
reaches the bottom of the viewport (content is clipped by the screen's lower
edge), the harness drags in segments to capture strips (a `sim.touch` drag plus
the `scroll.top`/`bottom` ground truth from `sim.tree`) and stitches them into a
`368 x (448 + reachable scroll amount)` full-page image: the baseline size is
the page's real height (for example `368x674` for `settings/about`), and the
first 448 rows are byte-identical to a single-frame screenshot in the same state
(the page chrome is preserved). A page whose scroll container lies entirely
within the viewport (such as the `recorder/files` list), or whose tail does not
exceed the LVGL drag threshold (`MIN_REACHABLE_TRAVEL`), is output as a single
`368x448` frame.
Content below the fold (`flags.visible` false) participates in the checks as
well: lint uses `_walk_on_screen` (skipping only `flags.hidden` subtrees), and
`single_line`, `expect_visible`, `expect_image`, and the baselines all cover
rows below the fold.

Label display rules read the rendering structure from `sim.tree` directly
(`long_mode`, `lines`) rather than the raw string: `single_line` requires
`len(lines) == 1`; WRAP text whose required line height exceeds `content_h + 2`
reports `clipped text`, and missing or incomplete line evidence reports a lint
error; clipping by a non-vertically-scrolled ancestor reports
`clipped by parent`, and text ending in `...` reports `truncated text` (a state
can allow it with an `allow_truncation` prefix); a multi-line paragraph matched
by
`balanced_prose` must not have fewer than 3 clusters on its last line, and must
not start a line with a closing punctuation mark or end a line with an opening
one.

The states of the same page share one sim session, and `set_*` state persists
across states (for example the Wi-Fi scan list is not cleared by switching to
the next state), so every state must be self-sufficient: the `home/root` control
center state explicitly does `set_bluetooth {enabled:false}` so that the
Bluetooth tile does not depend on a `bound` value left over from a previous
state.

Pages do not share a session: when `review_pages.py` launches sim itself, each
page uses an independent process (independent NVS and SD directories) and
rebuilds the folder fixture after starting. Otherwise a page that ends with a
`faulted`/`unmounted` medium would be inherited by the next page, and the pixel
baseline would no longer describe its own page — this pollution once manifested
as `recorder/files/detail` consistently gaining an extra "storage card or audio
unavailable". The cost is one cold start per page; when driving an external sim
with `--no-launch` a single session is kept and this isolation is not applied.

Every scenario gets an independent sim process + independent NVS directory (the
resident-app policy matches a cold start). Scenarios live in `sim/ci/scenarios/`
(`run_ci.sh` walks that directory, there is no separate manifest):
`all_apps.json` (text assertions for each built-in App's main page +
screenshots), `smoke_pages.json` (navigation/gestures/multiple pages),
`weather_flow.json` (the real weather pipeline: the `sim_http` script layer is
fed `sim/ci/fixtures/*.json`, validating location→current/hourly/`daily` parsing
and rendering, and opening the forecast subpage), `pm_lifecycle.json` (screen
off/wake), `recorder_playback_pm.json` (screen off then wake during playback:
the detail page keeps "playing/stopped", and returns to "play" after stopping;
screen off must not terminate recorder_service playback), and
`agent_contract.json` (parameter errors, pause, and screenshot contracts). Tree
assertions are the primary gate.

The `flybirds_restart_regression` action in `flybirds.json` only scores 1
through the live tree and the touch closed loop, then verifies that reopening
the HUD
shows 0, a second zero-score settlement, and a high score of 1; no seed or
production cheat entry is set. HUD/settlement values are limited to their own
visible container, and numbers under a hidden ancestor do not participate in
assertions. Scoring advances at most 360 frames of 33 ms, and each settlement
waits at most 120 frames; an RPC error, an early death, or a timeout fails
outright. In-field touch points avoid the system left-edge back gesture zone,
and a short tap does not additionally fast-forward one second; the settlement
screenshot waits for the card fade-in to finish.

Determinism relies on frozen data: the scenario's first step is
`set_time/set_power/set_imu/set_wifi`, and the UI stability criterion is the
frame hash unchanged for two consecutive steps + `lv_anim_count_running()==0`.
The PNG auxiliary gate is off by default.

TSan (WSL2 requires `setarch -R`, same as
app_core/tests/host/README.md):

```sh
cmake -S sim -B build/sim-tsan -G Ninja -DSIM_SANITIZER=thread
cmake --build build/sim-tsan
setarch $(uname -m) -R build/sim-tsan/microtech_sim --headless --ci \
    --res-dir build/sim/sim_res_fs --nvs-dir /tmp/sim-tsan-nvs &
python3 sim/tools/run_scenarios.py sim/ci/scenarios/all_apps.json
```

## PM Policy and Known Environment Characteristics

- **Always-on by default**: after startup_commit, `sim_runtime_boot` calls
  `app_manager_pm_set_timeout_ms(-1)` + `set_standby_delay_ms(-1)` (the
  firmware's "never" profile real path). Reason: PM uses the real wall clock
  (unaffected by the `--ci` tick freeze), and a 30s screen-off drags the CI
  session into a stalled mailbox (synchronous ui_call blocks forever), disabled
  touch, and black frames.
- **Screen-off is behavior to test, not environment noise**: the agent's
  `sim.pm {off_ms,standby_ms,get}` (a public API wrapper) + the
  `pm_lifecycle.json` scenario: short timeout→black frame→power click wake.
- **WSL mirrored networking**: connecting to the agent port before boot finishes
  yields a silent SYN timeout instead of RST-refused (a characteristic of
  mirrored's shared localhost routing, not a sim defect); `dev.py` already waits
  60s for readiness, and for manual debugging check the listener first with
  `ss -tln | grep 5002`.
- Exit paths: closing the window, `sim.exit`, and SIGTERM all set the exit flag;
  `dev.py` additionally has a PID kill backstop.

## Threading and Pixel Model

- The LVGL worker owns `lv_timer_handler` exclusively, the main thread pumps
  SDL, and the agent thread only follows the lock discipline table;
- The only pixel path: flush_cb → `custom_draw_bitmap` →
  `esp_lcd_panel_draw_bitmap` (sim_bsp blits into the 368×448 RGB565 FB) →
  synchronous `lv_display_flush_ready`;
- The host must not use `lv_draw_sw_rgb565_swap` (the on-device swap only serves
